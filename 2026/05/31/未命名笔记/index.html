1. 缓存查询流程（Cache-Aside 模式）

  • 热点菜品可设置随机过期时间，防止同时失效。

五、注意事项（基于常见教学要点）

  1. 缓存穿透：大量请求查询一个不存在的菜品 ID → 每次都会查数据库。
    解决方案：使用布隆过滤器，或缓存空值（redis.setex(key, 60, null)）。

  2. 缓存雪崩：大量缓存同时过期，导致数据库瞬间压力激增。
    解决方案：设置不同的随机过期时间；或使用二级缓存（本地缓存 + Redis）。

  3. 缓存击穿：一个热点缓存过期，大量并发请求同时查询数据库。
    解决方案：使用互斥锁（如 SETNX），只允许一个线程重建缓存。

  4. 数据一致性：更新数据库后，删除缓存更稳妥（Lazy 淘汰），或使用消息队列异步更新。

六、总结

  • 核心思想：利用 Redis 的高性能内存存储，缓存菜品数据，降低数据库负载。
  • 实现要点：合理选择数据结构、设置过期时间、处理缓存异常问题。

Spring Cache 笔记

1. 定义

Spring Cache 是一个框架，实现了基于注解的缓存功能。只需在方法上添加一个简单的注解，即可启用缓存逻辑。

2. 核心特点

  • 抽象层：Spring Cache 提供了一层缓存抽象，不绑定具体缓存实现。
  • 可切换底层实现：底层可以灵活切换不同的缓存技术，例如：
    • EHCache
    • Caffeine
    • Redis

3. Maven 依赖（Spring Boot 2.7.3）

4. 使用方式（概述）

  • 通过注解（如 @Cacheable、@CacheEvict、@CachePut 等）实现缓存读写操作。
  • 需要在配置类上添加 @EnableCaching 启用缓存支持。

AI 总结: ### Spring Cache 笔记

常用注解

1. @EnableCaching

  • 作用：开启缓存注解功能。
  • 使用位置：通常加在 Spring Boot 启动类上。

2. @Cacheable

  • 作用：在方法执行前先查询缓存中是否有数据。
    • 如果有数据，则直接返回缓存数据；
    • 如果没有缓存数据，则调用方法并将方法的返回值放入缓存中。

3. @CachePut

  • 作用：将方法的返回值放入缓存中（无论缓存中是否已存在，都会更新缓存）。

4. @CacheEvict

  • 作用：将一条或多条数据从缓存中删除（通常用于清除过期或无效的缓存）。
